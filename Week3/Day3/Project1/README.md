# ETL AI Automation Using n8n
## Week 3 – Day 3 Project Documentation

## 1. Project Overview

This project uses **n8n** to build an AI-assisted ETL workflow for reviewing and cleaning employee data. The workflow starts with an uploaded Excel workbook, extracts the employee records, sends the data and cleaning rules to an AI model, processes the model response using JavaScript, and converts the final records into an Excel output file.

**Main objective:** turn a source spreadsheet into a reviewed spreadsheet that contains employee data plus a record-level status and issue descriptions.

> **Important:** The first node is named **CSV Upload** in the screenshot, but the supplied input file is an `.xlsx` workbook. The Extract From File node is configured/displayed as **Extract From XLSX**. Make sure the upload/input node accepts the file type you actually upload. If it only accepts CSV, save the source sheet as CSV first or change the input setup to support XLSX.

### Input workbook structure

The input workbook has two worksheets:

- **Dirty Employee Data** — 50 employee records and 50 columns, plus the header row.
- **Data Dictionary** — field names and descriptions.

In the Extract From File node, select or verify **Dirty Employee Data** as the data source. Do not process the Data Dictionary as if it were employee records.

### Output workbook structure

The supplied `Output.xlsx` contains one worksheet with 50 data rows and 64 columns, including the employee fields and additional data-quality result columns. The exact output columns depend on the response returned by the LLM and the JavaScript node.

## 3. Tools Used

- **n8n Cloud** — connects and runs the workflow nodes.
- **CSV Upload** — the input/upload node shown in the workflow screenshot.
- **Extract From File (Extract From XLSX)** — extracts worksheet rows from the uploaded workbook.
- **Basic LLM Chain** — sends the cleaning instructions and employee data to the model.
- **OpenAI Chat Model** — the model connected to the Basic LLM Chain.
- **Code in JavaScript** — parses and reshapes the AI response.
- **Convert to File (Convert to XLSX)** — generates the final Excel file.
- **Microsoft Excel** — used to review the source and result files.

## 4. Workflow Architecture

The workflow shown in the n8n screenshot is:

```text
CSV Upload
    |
    v
Extract From File (Extract From XLSX)
    |
    v
Basic LLM Chain  <---- OpenAI Chat Model
    |
    v
Code in JavaScript
    |
    v
Convert to File (Convert to XLSX)
    |
    v

```

The main workflow runs from left to right. The **OpenAI Chat Model** is connected to the **Model** input of the Basic LLM Chain; it is a supporting model connection, not another node in the main left-to-right data path.

### Step 2 — Upload the source file (CSV Upload)

**Purpose:** provide the employee workbook to the workflow.

1. Click the **CSV Upload** node.
2. Review its input/upload configuration and confirm which file type it accepts.
3. Upload `employee_sample_data_50_fields_50_records(1).xlsx` if XLSX is supported by this node.
4. If the node only accepts CSV, open the input workbook in Excel and save the **Dirty Employee Data** worksheet as a `.csv` file, then upload that CSV instead.
5. Run or test the node and confirm that a file/binary payload is available to the next node.

**Expected result:** the uploaded file is available as input for the extraction node.

**Common issue:** the node label says CSV, while the next node says Extract From XLSX. The input file type and the extractor must agree. Do not assume that a node accepts XLSX solely because the workflow has a later XLSX extraction node.

### Step 3 — Extract the worksheet (Extract From File)

**Node shown:** `Extract From File`  
**Operation shown:** `Extract From XLSX`

**Purpose:** read the Excel workbook and turn its worksheet rows into structured data that downstream nodes can process.

1. Open **Extract From File**.
2. Verify that the operation/file format is set to **Extract From XLSX**.
3. Set the input binary property to the binary field produced by the previous node. The exact property name depends on the upload node's output; inspect the previous node's output rather than guessing the name.
4. Select or verify the **Dirty Employee Data** worksheet if the node offers a sheet selector. If the node extracts one sheet at a time, choose the employee-data sheet, not the Data Dictionary.
5. Execute this node by itself.
6. Inspect the output table. Confirm that fields such as `Employee ID`, `Employee Name`, `Employee Salary`, `Email Address`, and `Department` are present.

**Expected result:** one structured item per employee record, with the original field names.

**Validation:** the source worksheet has 50 employee records. If the extraction output has no rows, the wrong binary property, file format, or worksheet may have been selected.

### Step 4 — Configure the AI prompt (Basic LLM Chain)

**Purpose:** instruct the language model to review employee records using explicit cleaning rules.

1. Open the **Basic LLM Chain** node.
2. Find the prompt/input field used by the chain.
3. Pass the employee records from the Extract From File node into the prompt. Use n8n's expression picker to reference the actual incoming data; do not type a guessed field path.
4. Add the cleaning instructions. The following is a prompt template you can adapt to the actual input structure:

```text
You are an employee data-cleaning assistant.

Review the employee records supplied in the input.

Rules:
1. Trim leading and trailing spaces from text values.
2. Standardize employee names to title case without changing their meaning.
3. Convert email addresses to lowercase.
4. Identify missing or invalid email addresses.
5. Standardize department names only when the intended department is clear.
6. Identify duplicate email addresses across the supplied records.
7. Flag negative or non-numeric salary values.
8. Preserve Employee ID exactly as provided.
9. Do not invent missing values or infer information that is not present.
10. Preserve all other source fields unless a clear normalization rule applies.
11. For each record, return the cleaned fields, a status, and an issues array.
12. Use status "Needs Review" when one or more issues are found; otherwise use "Clean".
13. Return valid JSON only. Do not include Markdown fences, comments, or explanatory text outside the JSON.

Return one result per input employee. Use this structure:
{
  "records": [
    {
      "Employee ID": "original ID",
      "status": "Clean or Needs Review",
      "issues": ["description of each issue"]
    }
  ]
}

Include all original employee fields in each returned record, not only the example fields above.
```

**Important prompt notes:**
- Make sure the model receives the employee rows, not just the instruction text.
- If all 50 rows and 50 columns exceed the model's context or output limit, process smaller batches instead of sending the whole dataset in one request.
- Ask for JSON-only output so the next JavaScript node can parse it reliably.
- AI is not a replacement for business rules. Verify any proposed department mappings and invalid-data flags before relying on the output.

### Step 5 — Connect and configure OpenAI Chat Model

**Purpose:** provide the LLM used by the Basic LLM Chain.

In the screenshot, the **OpenAI Chat Model** node is connected to the **Model** connector beneath Basic LLM Chain.

1. Open **OpenAI Chat Model**.
2. Choose the intended model from the models available to your account.
3. Select valid OpenAI credentials stored in n8n.
4. Review any available model parameters. Use settings appropriate for consistent structured output, if supported.
5. Test the model connection.
6. Return to Basic LLM Chain and confirm that the Model connection is attached.

**Security:** store API keys in n8n Credentials. Do not place API keys in the prompt, JavaScript, README, screenshots, or GitHub repository.

**Expected result:** Basic LLM Chain can call the configured model and return a response.

### Step 6 — Process the model response (Code in JavaScript)

**Purpose:** convert the response from the Basic LLM Chain into individual JSON items suitable for an Excel file.

1. Open **Code in JavaScript**.
2. Inspect the input from Basic LLM Chain to identify the exact field containing the AI response. The field name can vary with the node output and configuration.
3. Parse the response as JSON. If the model wraps JSON in Markdown fences, remove the fences only if necessary; preferably configure the prompt to return JSON only.
4. Extract the `records` array (or the actual array structure used in your model response).
5. Return one n8n item for each employee record.
6. Preserve the original employee fields, the `status` field, and the `issues` array.
7. Add error handling for invalid JSON or a missing records array. Do not silently return fabricated employee information.

**Conceptual JavaScript pattern** (adapt the response field name to the actual Basic LLM Chain output):

```javascript
// First inspect the incoming item in n8n and replace `response`
// with the actual field that contains the model's JSON response.
const raw = $input.first().json.response;

const parsed = typeof raw === 'string' ? JSON.parse(raw) : raw;
const records = Array.isArray(parsed)
  ? parsed
  : parsed.records;

if (!Array.isArray(records)) {
  throw new Error('The AI response does not contain a records array.');
}

return records.map(record => ({
  json: {
    ...record,
    status: record.status ?? 'Needs Review',
    issues: Array.isArray(record.issues) ? record.issues : []
  }
}));
```

This is a **template, not guaranteed drop-in code**: your Basic LLM Chain may use a field other than `response`. Open the node's execution output and replace that field reference with the real one. If the chain returns the JSON in a different structure, adjust the parser accordingly.

**Expected result:** the Code node outputs one JSON item per employee, with the employee fields plus `status` and `issues`.

### Step 7 — Convert the results to Excel (Convert to File)

**Node shown:** `Convert to File`  
**Operation shown:** `Convert to XLSX`

**Purpose:** convert the processed JSON items into an Excel workbook.

1. Open **Convert to File**.
2. Select or verify the **Convert to XLSX** operation.
3. Confirm that the input comes from **Code in JavaScript**.
4. Configure the output file name if the node provides that option. Use `Output.xlsx`.
5. Execute the node.
6. Download the binary file from the node's output using the available download option.

**Expected result:** an Excel file containing the processed employee records.

**Output columns:** depending on how n8n flattens the JSON, the `issues` array may appear as numbered columns such as `issues.0`, `issues.1`, and so on. Review the output and adjust the structure if you prefer a single issue-summary column.

## 6. Data-Cleaning Rules

| Field or issue | Expected handling |
|---|---|
| Employee name | Trim outer spaces and use title case |
| Email address | Trim spaces and convert to lowercase |
| Missing email | Flag for review; do not invent an address |
| Invalid email | Flag for review |
| Duplicate email | Identify matching email addresses across records |
| Department | Standardize only when the correct mapping is clear |
| Salary | Flag negative or non-numeric values |
| Employee ID | Preserve exactly as supplied |
| Other fields | Preserve unless a clearly defined rule applies |
| Record status | `Clean` or `Needs Review`, based on the identified issues |
| Issues | An array of concise descriptions explaining what needs attention |

## 8. Troubleshooting

| Issue | Recommended check |
|---|---|
| XLSX upload fails | The first node is labelled CSV Upload. Check accepted file types or convert the employee worksheet to CSV. |
| Extract node returns no data | Verify the binary property name, file format, and selected worksheet. |
| Data Dictionary is extracted | Select the `Dirty Employee Data` worksheet. |
| LLM returns prose instead of JSON | Strengthen the JSON-only instruction and validate the model response. |
| JavaScript says the response field is undefined | Inspect Basic LLM Chain's output and replace the template's `response` field with the actual property. |
| JSON parsing fails | Inspect the raw model output; handle malformed responses and do not export unparsed text as employee records. |
| Fewer than 50 records appear | Check model output limits, truncation, parser logic, and whether records are being filtered. Consider batching. |
| Output has numbered issue columns | The `issues` array may be flattened during XLSX conversion. Keep as-is or map it to a readable summary field. |
| OpenAI request fails | Check n8n credentials, model availability, account limits, and error details. Never share API secrets. |
